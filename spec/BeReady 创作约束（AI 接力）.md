# BeReady 创作约束（AI 接力）

> 本文是写给未来参与 BeReady 内容创作的 AI 的**约束文档**。
>
> 它与三份既有规范的关系：
>
> - `spec/core.md` —— 第一原则（用户亲定，最高优先级）；
> - `spec/BeReady 内容架构设计.md` —— 愿景与信息架构（背景参考）；
> - `spec/BeReady 文件组织与知识节点管理规范 2.md` + `spec/BeReady Wikilink 命名与链接规范.md` —— 结构与链接规则（仍然有效）；
> - **本文 —— 把第一原则落成可执行的写作与操作约束。**
>
> 冲突时的优先级：**core.md > 本文 > 其他规范**。

---

# 1. 第一原则（不可违背）

创作背景：**社会系统崩溃**——战争、灾害、末日等，人与人不再信任，"我"如何生存。

- 所有内容必须与此背景**密切相关**；
- 一切以**简洁实用**为主；
- **杜绝和平时期的科普**。

自检（每条内容过一遍）：

> 一个孤立无援、叫不到任何帮助的人，看完这条内容能不能**立刻用**？
> 不能 → 不收、或重写到能为止。

### 三条扩展方向（core.md 2026-09-17 更新，同样不可违背）

1. **非城市场景是默认视角之一** —— 崩溃后城市反而不如野外、丛林、山区宜居；写作不默认"在家/城市"，主动覆盖野外、丛林、山区，就地取材。
2. **药品是基础储备** —— 之初就应搜集常见药品及用途；以后逐步补中草药。
3. **可自制资源写核心制作步骤** —— 凡是不需要现代工业就能做出来的资源，要记入并写出核心制作步骤（如木炭制作）。

# 2. 口吻与篇幅

- **手册，不是教材。** 命令式、清单式、短句。
- 写作顺序：**行动 → 判断 → 注意 → 原理**。原理能删则删，必须保留时压缩进"注意"或一句话导语。
- 删除"例如"式铺陈、层层条件 hedge、"为什么"长段落。
- 参考篇幅：改写后的火章节约为原文的 50–60%。
- 推荐结构（非强制）：导语一句 → 立即知道 → 怎么做 → 注意 → 继续了解。
- **不写"来源"节。** 不引用 WHO / CDC / FEMA / NFPA 等机构名充门面；这些资料可作事实参考，但不得作为口吻模板。

### 引言规则（`> ` 导语）

- **引言不重复设定。** "崩溃 / 失序"这条背景只在 `index.md` 交代一次；引言里不再写"崩溃后没有 X、没有 Y"。引言只回答一句：**这一章替你挡掉什么死法、解决什么麻烦。**
- 反面（曾全库通用，19 个能力首页共用一个句式）：`崩溃后没有自来水、没有下水道、没有垃圾清运、没有医院。`
- 正面：`最可能先杀死你的不是饿、不是冷，是脏病。`
- **各章换角度切入，避免又形成新模板。** 可用角度：后果直给 / 依赖落差（"你冲马桶、倒垃圾，靠的是水厂和清运车，不是你自己"）/ 反常识 / 数字锚点 / 常见错法 / 分水岭。
- 引言里"没人兜底"只在**它是本章论证前提**时保留（如生产、种植类），改写为"X 不会再给你补货"，不用"崩溃后"起头。
- 范围：正文深处的"崩溃后"是判断依据，保留；只清理引言。

# 3. 反面清单（出现即改写）

以下特征 = 和平期科普，一律清除：

- 假设系统只是暂时中断："停电几小时冰箱能撑多久"、"等救援到达"、"拨打抢修电话"；
- 假设社会协作正常：邻里协商、物业、投诉、报警、燃气公司上门、公开的分配规则；
- 假设规则与监管存在：禁火通告、火险等级查询、法律赔偿；
- 依赖和平期设施作为唯一解法：烟雾报警器、外卖、超市补货；
- 教材腔：背景介绍、原理长文、来源列表、术语解释优先于动作。

正确的替换方向：

> "没人来修、没人来救、没人替你兜底；资源用一天少一天；后果全由自己扛。"

# 4. 红线：不写人视人为威胁

- **正文中不得把他人刻画为威胁对象**（避免挑起麻烦）：不写"防范抢劫"、"陌生人会攻击你"、"对付入侵者"这类内容。
- **可以写**自我保护类措辞（已获用户确认）：
  - **低调** —— "需要低调时，控制火的时间和位置"；
  - **减少暴露** —— "烟、光、气味传得很远，是暴露途径"；
  - **避免冲突** —— "能绕开就绕开"。
- 原则：只讲**如何降低自己的可见度和风险**，不讲**如何应对具体的人**。

---

# 5. 暴露意识（新增维度）

崩溃期特有的权衡，相关节点必须考虑：

- 火：烟、火光、气味（见 `fire/L1/fire-environment.md` 第五变量、`fire/L2/outdoor-fire-safety.md` 低调用火）；
- 水、食物、庇护同理：获取和储存行为是否显眼、是否留下痕迹；
- 写法只到"降低暴露"为止，不延伸到"防谁"（见第 4 条红线）。

---

# 6. 结构规则（仍然有效，摘要）

- 目录：`capabilities/<capability>/<level>/<node>.md` 是唯一知识主树；`scenarios/<scenario>.md` 是场景/整合主题（组合入口，通过 Wikilink 组合已有能力，不建第二套 Level、不复制知识）。每个节点只有一个 Canonical 归属，不复制。
- front matter 四件必须齐且自洽：

```yaml
---
filename: capabilities/{capability}/{level}/{node}.md   # 与实际路径一致
title: {全库唯一，与正文 H1 一致}                         # Wikilink 第一解析目标
level: L1                                               # 与所在目录一致
category: {capability}
status: draft
---
```

- Wikilink：默认写 `[[title]]`，可 `[[title|别名]]`；不写路径、不带 `.md`；
  index 里指向未建节点的链接是**预告清单**，不是死链，不要批量"修"。
- **结构弹性（core.md 第二条）**：L1/L2/L3 仅作参考，不死板逐级，宁缺毋滥；不为凑层级、凑闭环造节点。

# 7. 权限边界（用户亲定）

| 目录 | 权限 |
|---|---|
| `capabilities/` | **可随意调整**（新建、改写、移动，遵守第 6 条） |
| `scenarios/` | **可随意调整**（场景/整合主题组合入口，2026-09-19 起） |
| 工作区根目录 | **允许按原规划（规范 §40）新建合适的区域目录**；顶层区域 = `capabilities/` + `scenarios/`（原「仅限 capabilities/」已解除） |
| `_raw/` | 原始输入区，只增不改，不动 |
| `spec/` | 原始设计文档，不动；新增规范需用户明确要求（本文即为一例） |
| `__everkm/` | 平台运行时，不动 |
| `_progress/` | 交接记录，每轮结束追加新编号文件（唯一进度来源） |

---

# 8. 每轮工作流程

1. 开始前读：`spec/core.md`、本文、最近的 `_progress/NNN.md`；
2. 写作/改写按第 1–5 条执行；
3. 结束时校验（见第 9 条）并产出 `_progress/NNN.md`（编号 = 现有最大 + 1）：本轮完成 / 关键判断 / 新产生的待完善节点 / 下一步；
4. 不确定归属、Level、去留的问题：**记入 Progress，不擅自扩大任务**。

# 9. 完成前校验清单

- [ ] 每条内容过了第 1 条的"崩溃测试"；
- [ ] 无第 3 条反面清单特征（救援、报修、监管、机构引用）；
- [ ] 未触碰第 4 条红线（没有"防人"内容，自我保护措辞合规）；
- [ ] 覆盖了非城市场景（不默认城市）；可自制资源写了核心制作步骤；涉及药品时按"常见药品优先、中草药后续"；
- [ ] front matter 四件齐全且与路径、目录、H1 一致；
- [ ] title 全库唯一；wikilink 用 title 写法；未新增真死链（预告链接除外）；
- [ ] 未改动 `_raw/`、`spec/`、`__everkm/` 中的既有文件；
- [ ] `_progress/` 已追加本轮记录。
