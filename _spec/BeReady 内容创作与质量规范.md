# BeReady 内容创作与质量规范

> 本文把 `_spec/core.md` 的核心纲领落实为可执行的内容质量要求，适用于人和 AI。
>
> 文档职责：
>
> - `_spec/core.md`：最高纲领和内容取舍依据；
> - 本文：节点的边界、语言、可操作深度和安全红线；
> - 文件组织与 Wikilink 规范：结构与链接；
> - 贡献与审核规范：社区、AI、Review 和合并；
> - `_PLAN.md`：候选缺口和路线图，不是规范。
>
> 完整关系见 `_spec/BeReady 规范索引.md`。发生冲突时，以核心纲领为准。

---

# 1. 内容判断标准

BeReady 以极端情况下能否解决问题为检验标准，把能力拆解到日常可以学习和训练的层面。

每个节点先回答：

- 它能否帮助没有专业训练的普通人理解问题、判断风险或采取行动？
- 它能否在资源受限、基础设施失效或环境变化时提高解决问题的能力？
- 它是否可以在日常生活中学习、练习或验证？

只提供背景知识、猎奇信息或日常优化，却不能改善实际判断和行动的内容，不进入核心体系。

社会系统失效是重要压力测试，不是所有节点必须采用的固定叙事。日常可用不等于和平时期泛科普；应删除的是与行动无关的铺陈，而不是日常训练场景。

### 必须考虑的方向

1. **环境不能只默认城市和室内**：根据主题考虑农村、野外、丛林、山区，以及温度、湿度、季节和工具条件。
2. **药品重在可靠使用**：可记录常见药品及用途；剂量、禁忌和替代方案必须有可靠依据。中草药不能在依据不足时写成处方替代。
3. **可自制资源写关键步骤**：不依赖现代工业即可制作的资源，在符合节点边界时写出材料、动作、完成标准和风险。

---

# 2. 口吻与篇幅

- **手册，不是教材。** 清楚、直接、具体，按需要使用步骤、清单和短段落。
- 写作顺序优先采用：**行动 → 判断 → 注意 → 必要原理**。原理只保留到能帮助判断和迁移方法的程度。
- **简洁不等于空洞。** 操作内容应写清用什么、手怎么动、做到什么程度算完成、失败时有什么信号。
- 删除空泛背景、重复结论和“保持清洁”“注意安全”这类无法执行的正确废话。
- 推荐结构（非强制）：导语一句 → 立即知道 → 怎么做 → 注意 → 继续了解。
- 正文不靠机构名称增加权威感。资料和实践依据保留在审核过程；正文只在来源本身影响适用条件时说明。

### 引言规则（`> ` 导语）

- 引言只说明这个节点解决什么问题，或错误处理会造成什么后果。
- 不重复整套项目设定，不用“崩溃后没有……”作为全库统一模板。
- 不用猎奇、恐惧和夸张制造阅读动力。
- 系统失效、资源受限或无人支援只有在影响当前方法时才写，并说明它改变了什么判断。

---

# 3. 反面清单

出现以下情况时应改写：

- 只解释概念，不帮助判断或行动；
- 只给理想条件下的唯一方案，没有资源受限时的替代方法；
- 把“等待救援、等待恢复、联系服务机构”作为唯一结论；
- 默认监管、供应、通信和专业支援始终存在；
- 用危机、冲突或末日想象制造情绪，却没有提供可执行能力；
- 术语、机构和来源列表先于使用者需要做的事情；
- 为了完整而补写未经验证的数字、参数和经验。

可以写和平时期的设施和专业支援，但要区分：

- 当前仍可利用时，怎样正确利用；
- 它们失效后，哪些判断和替代方案仍然成立；
- 普通人不能安全替代的专业操作是什么。

---

# 4. 红线：不写人视人为威胁

- **正文中不得把他人刻画为威胁对象**：不写“防范抢劫”“陌生人会攻击你”“对付入侵者”这类内容。
- **可以写**自我保护类措辞：
  - **低调**：需要低调时，控制火的时间和位置；
  - **减少暴露**：烟、光、气味传得很远，是暴露途径；
  - **避免冲突**：能绕开就绕开。
- 只讲如何降低自己的可见度和风险，不讲如何应对具体的人。

---

# 5. 暴露与冲突风险

在资源受限、环境危险或需要保持低调的场景中，相关节点应考虑：

- 火：烟、火光、气味；
- 水、食物、庇护：获取和储存行为是否显眼、是否留下痕迹；
- 写法只到“降低暴露”为止，不延伸到“防谁”。

---

# 6. 结构规则

- 结构以 `_spec/BeReady 文件组织与知识节点管理规范 2.md` 为准。
- 链接以 `_spec/BeReady Wikilink 命名与链接规范.md` 为准。
- 每个节点只有一个 Canonical 归属；场景通过链接组合已有能力，不复制知识正文。
- Level 是能力发展参考，不为凑层级、凑闭环制造节点。
- 已有知识通过必要说明和 Wikilink 复用，不在多个节点中重复展开。

---

# 7. 完成前校验清单

- [ ] 内容通过核心纲领的判断：关键时刻能提高生存概率或解决问题能力，并能在日常学习或训练。
- [ ] 普通人能照着完成操作，或明确知道何时不能自行操作。
- [ ] 写清必要材料、动作、完成标准、失败信号、限制和替代方案。
- [ ] 没有用危机叙事替代实用内容，也没有只写日常优化而失去极端检验。
- [ ] 未触碰第 4 条红线。
- [ ] 操作条件包含与主题相关的城乡、室内外、气候、工具和资源差异。
- [ ] 事实、数字、剂量和参数有依据；个人经验没有被写成普遍规律。
- [ ] 没有与已有节点重复；结构、front matter 和 Wikilink 符合对应规范。

---

# 8. 工作流

- 研究缺口时只输出边界、结构、已有知识和待验证问题，不直接改正文。
- 节点范围确认后再写；多个节点先划清职责，避免重复。
- 社区意见和个人经验按 `_spec/BeReady 贡献与审核规范.md` 处理。
- 不确定归属、Level、事实或去留时，记录为待研究，不靠猜测完成。
