# BeReady 规范索引

本文说明各文档的职责和冲突处理顺序。规范未明确授权时，不因追求完整而扩大修改范围。

## 最高纲领

`_spec/core.md` 是项目最高判断依据。它回答 BeReady 为什么存在、服务谁、什么知识属于核心体系。

任何写作口吻、阶段计划、目录结构、运营目标或 AI 工作流，都不能覆盖核心纲领。发生冲突时，以核心纲领为准。

## 生效规范

### 内容

`_spec/BeReady 内容创作与质量规范.md`

规定知识节点的内容边界、可操作深度、语言、安全红线和质量检查。

### 结构

- `_spec/BeReady 文件组织与知识节点管理规范 2.md`
- `_spec/BeReady Wikilink 命名与链接规范.md`

规定节点的 Canonical 归属、Capability、Level、文件组织和 Wikilink。结构规范不能替代内容判断。

### 贡献治理

`_spec/BeReady 贡献与审核规范.md`

规定社区反馈、AI 整理、人工审核和 Git 记录怎样进入正式知识库。

### 社区运营

`_spec/BeReady 社区运营规则.md`

规定如何通过具体问题寻找反馈、邀请贡献和验证社区闭环。传播数据不能替代知识判断。

## 路线图与设计参考

`_spec/_PLAN.md` 是内容缺口和后续工作路线图，不是已经确认的知识结构。只有标为“已确认”的事项才能直接进入实施。

`_spec/BeReady 内容架构设计.md` 记录完整的架构推演和产品设想。涉及当前文件、链接和内容操作时，以本索引列出的生效规范为准。

`_spec/_archives/` 保存历史规范，不参与当前决策。

## 临时材料与执行适配

`_tmp/` 是信息中转站。草案在被确认并迁入正式规范前不具有约束力；迁入后以 `_spec/` 中的版本为准。

`.cursor/rules/` 是给 AI 的执行摘要，不是规范真源。规则必须服从 `_spec/core.md` 和对应的生效规范，不能自行增加项目原则。

## 按任务读取

- 创建或修改内容：核心纲领 + 创作约束 + 相关结构规范。
- 研究缺口：核心纲领 + `_PLAN.md` + 相关已有节点；研究结论先进入候选，不直接写成正式答案。
- 调整结构：核心纲领 + 文件组织规范 + Wikilink 规范；影响多节点时先提案。
- 处理社区贡献：核心纲领 + 贡献与审核规范 + 涉及领域的内容规范。
- 修改工具或检查脚本：同时核对它所实现的正式规范，避免规范和工具形成两套标准。
